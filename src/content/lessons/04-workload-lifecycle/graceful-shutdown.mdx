<Intro>
  <p>Graceful shutdown ensures in-flight requests complete before a Pod terminates. When Kubernetes sends SIGTERM, apps should stop accepting new requests, finish existing ones, then exit. The terminationGracePeriodSeconds sets the deadline. Use for: zero-downtime deployments, preventing data loss, clean connection handling.</p>
</Intro>

<table class="example-table">

    <FileHeader filename="graceful-shutdown-basic.yaml" />
    <Row last>
      <p slot="docs">The <code>terminationGracePeriodSeconds</code> gives your app time to shut down gracefully. Default is 30 seconds. After this period, Kubernetes sends SIGKILL. Set this higher than your longest request.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-server
spec:
  terminationGracePeriodSeconds: 60
  containers:
    - name: app
      image: my-app:v1
      ports:
        - containerPort: 8080
```
      </Fragment>
    </Row>

    <FileHeader filename="prestop-hook.yaml" />
    <Row>
      <p slot="docs">A preStop hook runs before SIGTERM is sent. Use it to deregister from service discovery, drain connections, or notify load balancers. The sleep gives time for endpoints to update before shutdown begins.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-server
spec:
  terminationGracePeriodSeconds: 60
  containers:
    - name: app
      image: my-app:v1
      ports:
        - containerPort: 8080
      lifecycle:
        preStop:
          exec:
            command:
              - /bin/sh
              - -c
              - sleep 10
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">The preStop sleep solves a race condition: Pod termination and endpoint removal happen concurrently. The sleep ensures kube-proxy updates before your app stops accepting connections.</p>
      <Fragment slot="code">
```yaml
lifecycle:
  preStop:
    httpGet:
      path: /prestop
      port: 8080
```
      </Fragment>
    </Row>

    <FileHeader filename="shutdown-sequence.yaml" />
    <Row last>
      <p slot="docs">Complete shutdown-aware deployment. The app handles SIGTERM by stopping new connections, waiting for in-flight requests, closing database connections, and exiting cleanly. Combined with preStop hook and sufficient grace period.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-server
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api-server
  template:
    metadata:
      labels:
        app: api-server
    spec:
      terminationGracePeriodSeconds: 120
      containers:
        - name: api
          image: api-server:v1
          ports:
            - containerPort: 8080
          lifecycle:
            preStop:
              exec:
                command: ["sh", "-c", "sleep 15"]
          readinessProbe:
            httpGet:
              path: /ready
              port: 8080
            periodSeconds: 5
```
      </Fragment>
    </Row>

    <FileHeader filename="connection-draining.yaml" />
    <Row last>
      <p slot="docs">For long-lived connections (WebSockets, gRPC streams), configure connection draining. The app tracks active connections and waits for them to close naturally or times them out during shutdown.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: websocket-server
spec:
  template:
    spec:
      terminationGracePeriodSeconds: 300
      containers:
        - name: ws
          image: websocket-server:v1
          env:
            - name: SHUTDOWN_TIMEOUT
              value: "280"
            - name: CONNECTION_DRAIN_TIMEOUT
              value: "60"
          lifecycle:
            preStop:
              exec:
                command:
                  - /bin/sh
                  - -c
                  - |
                    curl -X POST localhost:8080/admin/drain
                    sleep 15
```
      </Fragment>
    </Row>

    <FileHeader filename="job-graceful-shutdown.yaml" />
    <Row last>
      <p slot="docs">Jobs and batch workloads need graceful shutdown too. If terminated mid-processing, the job should checkpoint progress or mark items for retry. The activeDeadlineSeconds limits total runtime.</p>
      <Fragment slot="code">
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: batch-processor
spec:
  activeDeadlineSeconds: 3600
  template:
    spec:
      terminationGracePeriodSeconds: 300
      restartPolicy: OnFailure
      containers:
        - name: processor
          image: batch-processor:v1
          env:
            - name: CHECKPOINT_DIR
              value: "/data/checkpoints"
            - name: GRACEFUL_SHUTDOWN_TIMEOUT
              value: "290"
          volumeMounts:
            - name: data
              mountPath: /data
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: batch-data
```
      </Fragment>
