<Intro>
  <p>Admission webhooks intercept API requests before resources are persisted. ValidatingWebhooks reject invalid resources. MutatingWebhooks modify resources (inject sidecars, add labels). Misconfigured webhooks can block all deployments and crash clusters.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="validatingwebhook.yaml" />
    <Row>
      <p slot="docs">ValidatingWebhookConfiguration defines when to call your webhook. <code>rules</code> specify which resources and operations trigger validation.</p>
      <Fragment slot="code">
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: pod-policy
webhooks:
  - name: pod-policy.example.com
    rules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pods"]
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Configure the webhook service endpoint and TLS. The API server calls this service for each matching request.</p>
      <Fragment slot="code">
```yaml
    clientConfig:
      service:
        name: pod-policy-webhook
        namespace: webhook-system
        path: /validate
        port: 443
      caBundle: LS0tLS1CRUd...  # Base64 CA cert
    admissionReviewVersions: ["v1"]
    sideEffects: None
    timeoutSeconds: 5
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="mutatingwebhook.yaml" />
    <Row>
      <p slot="docs">MutatingWebhookConfiguration modifies resources. Common uses: inject sidecars (Istio), add default labels, set security context. Mutations happen before validation.</p>
      <Fragment slot="code">
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: MutatingWebhookConfiguration
metadata:
  name: sidecar-injector
webhooks:
  - name: sidecar.example.com
    rules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE"]
        resources: ["pods"]
    namespaceSelector:
      matchLabels:
        sidecar-injection: enabled
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Use <code>namespaceSelector</code> or <code>objectSelector</code> to limit scope. This prevents the webhook from affecting system namespaces.</p>
      <Fragment slot="code">
```yaml
    namespaceSelector:
      matchExpressions:
        - key: kubernetes.io/metadata.name
          operator: NotIn
          values:
            - kube-system
            - kube-public
    objectSelector:
      matchLabels:
        inject-sidecar: "true"
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="webhook-failurepolicy.yaml" />
    <Row>
      <p slot="docs"><code>failurePolicy</code> controls what happens when the webhook is unavailable. <code>Fail</code>: reject requests (safe but blocks deployments). <code>Ignore</code>: allow requests (risky but won't block).</p>
      <Fragment slot="code">
```yaml
webhooks:
  - name: critical-validation.example.com
    failurePolicy: Fail       # Block if webhook down
    timeoutSeconds: 10

  - name: optional-mutation.example.com
    failurePolicy: Ignore     # Allow if webhook down
    timeoutSeconds: 5
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>Critical</strong>: <code>Fail</code> policy with broken webhooks blocks ALL matching requests, including kube-system pods. This can crash your cluster. Always exclude system namespaces.</p>
      <Fragment slot="code">
```yaml
# DANGEROUS: Fails on all pods, including system
rules:
  - resources: ["pods"]
failurePolicy: Fail

# SAFE: Exclude system namespaces
namespaceSelector:
  matchExpressions:
    - key: kubernetes.io/metadata.name
      operator: NotIn
      values: ["kube-system", "kube-public"]
```
      </Fragment>
    </Row>
  </tbody>

    <TerminalHeader cmd="kubectl delete validatingwebhookconfiguration broken-webhook" />
    <Row>
      <p slot="docs"><strong>Emergency fix</strong>: Delete the webhook configuration to unblock deployments. This removes the webhook entirely until you fix and redeploy it.</p>
      <Fragment slot="code">
```bash
# If webhook is blocking all deployments:
$ kubectl delete validatingwebhookconfiguration broken-webhook
validatingwebhookconfiguration.admissionregistration.k8s.io "broken-webhook" deleted

# Deployments should now work
$ kubectl get pods -n kube-system
# Pods starting again
```
      </Fragment>
    </Row>
    <Row last terminal>
      <p slot="docs">Alternative: patch the webhook to <code>Ignore</code> failure policy temporarily while you fix the underlying issue.</p>
      <Fragment slot="code">
```bash
# Temporarily allow requests when webhook fails
$ kubectl patch validatingwebhookconfiguration broken-webhook \
    --type='json' \
    -p='[{"op": "replace", "path": "/webhooks/0/failurePolicy", "value": "Ignore"}]'

# Fix the webhook service, then restore Fail policy
$ kubectl patch validatingwebhookconfiguration broken-webhook \
    --type='json' \
    -p='[{"op": "replace", "path": "/webhooks/0/failurePolicy", "value": "Fail"}]'
```
      </Fragment>
    </Row>

    <FileHeader filename="webhook-service.yaml" />
    <Row last>
      <p slot="docs">The webhook must be highly available. Use multiple replicas, proper resource limits, and PodDisruptionBudget. A down webhook with <code>Fail</code> policy blocks deployments.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: pod-policy-webhook
  namespace: webhook-system
spec:
  replicas: 3                    # HA
  selector:
    matchLabels:
      app: pod-policy-webhook
  template:
    spec:
      affinity:
        podAntiAffinity:         # Spread across nodes
          requiredDuringSchedulingIgnoredDuringExecution:
            - topologyKey: kubernetes.io/hostname
      containers:
        - name: webhook
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
```
      </Fragment>
    </Row>
