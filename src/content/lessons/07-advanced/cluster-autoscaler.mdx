<Intro>
  <p>Cluster Autoscaler automatically adjusts the number of nodes based on pending pods. It adds nodes when pods can't be scheduled due to resource constraints, and removes underutilized nodes to save costs. Essential for handling variable workloads efficiently.</p>
</Intro>

      <p slot="docs">Cluster Autoscaler triggers scale-up when pods are Pending due to insufficient resources. It analyzes why pods can't be scheduled and adds appropriate nodes.</p>
      <Fragment slot="code">

```bash
default   web-abc123    0/1     Pending   0          5m

$ kubectl describe pod web-abc123 | grep -A5 Events
Events:
  Type     Reason            Message
  ----     ------            -------
  Warning  FailedScheduling  0/3 nodes available:
           3 Insufficient cpu.
```

    <FileHeader filename="cluster-autoscaler-deployment.yaml" />
    <Row>
      <p slot="docs">Cluster Autoscaler runs as a Deployment. Key flags: <code>--node-group-auto-discovery</code> finds node pools, <code>--scale-down-enabled</code> allows removing nodes.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cluster-autoscaler
  namespace: kube-system
spec:
  replicas: 1
  selector:
    matchLabels:
      app: cluster-autoscaler
  template:
    spec:
      containers:
        - name: cluster-autoscaler
          image: registry.k8s.io/autoscaling/cluster-autoscaler:v1.28.0
          command:
            - ./cluster-autoscaler
            - --cloud-provider=aws
            - --node-group-auto-discovery=asg:tag=k8s.io/cluster-autoscaler/enabled,k8s.io/cluster-autoscaler/my-cluster
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Configure scale-down behavior. <code>--scale-down-delay-after-add</code> prevents thrashing, <code>--scale-down-unneeded-time</code> sets how long a node must be underutilized.</p>
      <Fragment slot="code">
```yaml
          command:
            - ./cluster-autoscaler
            - --scale-down-enabled=true
            - --scale-down-delay-after-add=10m
            - --scale-down-unneeded-time=10m
            - --scale-down-utilization-threshold=0.5
            - --max-node-provision-time=15m
            - --balance-similar-node-groups=true
```
      </Fragment>
    </Row>

```bash
No scale-up: no node group can accommodate pod
```

    <Row last terminal>
      <p slot="docs">Common issues: pod requests too large for any node type, affinity rules blocking scheduling, PDB preventing node drain.</p>
      <Fragment slot="code">
```bash
# Pod requests more than max node size
$ kubectl logs ... | grep "no node group"
No scale-up: no node group can accommodate pod
  requesting cpu=8000m, max node has 4000m

# Pod blocked by affinity
Pod can't be scheduled due to node affinity

# Scale-down blocked by PDB
Cannot remove node: PodDisruptionBudget
```

    <FileHeader filename="pod-safe-to-evict.yaml" />
    <Row>
      <p slot="docs">Prevent pods from blocking scale-down with the <code>safe-to-evict</code> annotation. Use for pods that can be safely terminated (stateless, idempotent).</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: worker
  annotations:
    cluster-autoscaler.kubernetes.io/safe-to-evict: "true"
spec:
  containers:
    - name: worker
      image: worker:v1
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">By default, pods with local storage, not backed by a controller, or with restrictive PDBs block scale-down. Use annotations to override.</p>
      <Fragment slot="code">
```yaml
# Pods that block scale-down by default:
# - Pods with local storage (emptyDir with data)
# - Pods not managed by controller (bare pods)
# - Pods with PDB preventing eviction
# - Pods with "safe-to-evict: false" annotation

# This pod uses emptyDir but is safe to evict
annotations:
  cluster-autoscaler.kubernetes.io/safe-to-evict: "true"
```
      </Fragment>
    </Row>

    <FileHeader filename="nodepool-priority.yaml" />
    <Row>
      <p slot="docs">Use node pool priority to prefer cheaper instances. Lower priority pools are used first, falling back to higher priority (more expensive) pools when needed.</p>
      <Fragment slot="code">
```yaml
# AWS Auto Scaling Group tags
k8s.io/cluster-autoscaler/node-template/label/node-type: spot
k8s.io/cluster-autoscaler/enabled: "true"

# Autoscaler expander: priority
# Define priority in ConfigMap:
apiVersion: v1
kind: ConfigMap
metadata:
  name: cluster-autoscaler-priority-expander
  namespace: kube-system
data:
  priorities: |
    10:
      - spot-pool
    50:
      - on-demand-pool
```
      </Fragment>
    </Row>
    <Row last terminal>
      <p slot="docs">Configure expander strategy to control which node pool is scaled. Options: <code>random</code>, <code>most-pods</code>, <code>least-waste</code>, <code>priority</code>.</p>
      <Fragment slot="code">
```bash
# Use priority expander for cost optimization
--expander=priority

# Or least-waste for efficient bin-packing
--expander=least-waste

# Check current expander
$ kubectl get deploy cluster-autoscaler -n kube-system \
    -o jsonpath='{.spec.template.spec.containers[0].command}' \
    | tr ',' '\n' | grep expander
```
      </Fragment>
    </Row>

    <Row last terminal>
      <p slot="docs">Mix spot and on-demand instances for cost savings. Spot instances are cheaper but can be terminated. Use for stateless, fault-tolerant workloads.</p>
      <Fragment slot="code">
```bash
$ kubectl get nodes --show-labels | grep -E "spot|on-demand"
node-spot-1     node-type=spot
node-spot-2     node-type=spot
node-ondemand-1 node-type=on-demand

# Schedule critical workloads on on-demand
nodeSelector:
  node-type: on-demand

# Allow batch jobs on spot
nodeSelector:
  node-type: spot
tolerations:
  - key: "spot-instance"
    operator: "Exists"
```
      </Fragment>
    </Row>
