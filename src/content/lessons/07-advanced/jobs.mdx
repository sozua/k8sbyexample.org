<Intro>
  <p>Jobs run a task to completion. Unlike Deployments that run indefinitely, Jobs ensure a specified number of Pods successfully complete. Use for: migrations, batch processing, backups, one-time tasks.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="job.yaml" />
    <Row last>
      <p slot="docs">Job runs Pods until successful completion. <code>restartPolicy</code> must be <code>Never</code> or <code>OnFailure</code> (required). <code>backoffLimit: 3</code> retries 3 times before marking failed.</p>
      <Fragment slot="code">
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migrate
spec:
  template:
    spec:
      containers:
        - name: migrate
          image: my-app:v1
          command: ["python", "migrate.py"]
      restartPolicy: Never
  backoffLimit: 3
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="job-parallel.yaml" />
    <Row last>
      <p slot="docs">Job completion modes: <code>NonIndexed</code> (default) runs N identical Pods. <code>Indexed</code> assigns each Pod a unique index (0 to completions-1) via <code>JOB_COMPLETION_INDEX</code> env var for work partitioning.</p>
      <Fragment slot="code">
```yaml
spec:
  completions: 10
  parallelism: 3
  completionMode: Indexed
  template:
    spec:
      containers:
        - name: worker
          image: worker:v1
          command: ["./process-partition.sh"]
      restartPolicy: Never
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <Row last>
      <p slot="docs"><code>backoffLimit: 3</code> retries then Job fails. <code>activeDeadlineSeconds: 600</code> = must complete in 10 min. <code>ttlSecondsAfterFinished: 3600</code> = delete 1 hour after. <code>OnFailure</code> restarts container in same Pod; <code>Never</code> creates new Pod for each retry.</p>
      <Fragment slot="code">
```yaml
spec:
  backoffLimit: 3
  activeDeadlineSeconds: 600
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: OnFailure
```

    <Row last>
      <p slot="docs">Parallel Jobs have three modes. First example: fixed completion count (run 10 total, 3 at a time). Second example: work queue (no completions = Pods coordinate, done when any Pod exits 0). Third example: single Pod (default).</p>
      <Fragment slot="code">
```yaml
spec:
  completions: 10
  parallelism: 3
---
spec:
  parallelism: 5
---
spec:
  completions: 1
  parallelism: 1
```

    <FileHeader filename="cronjob.yaml" />
    <Row last>
      <p slot="docs">CronJobs run Jobs on a schedule using cron syntax (minute hour day-of-month month day-of-week). Schedule examples in code. Use <code>concurrencyPolicy</code> to control overlapping runs.</p>
      <Fragment slot="code">
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-backup
spec:
  schedule: "0 2 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: backup:v1
          restartPolicy: OnFailure
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="cronjob-policy.yaml" />
    <Row last>
      <p slot="docs"><code>concurrencyPolicy</code>: <code>Allow</code> (default) allows concurrent Jobs, <code>Forbid</code> skips if previous running, <code>Replace</code> kills previous. <code>successfulJobsHistoryLimit: 3</code> keeps 3 completed. <code>startingDeadlineSeconds: 60</code> must start within 60s of schedule.</p>
      <Fragment slot="code">
```yaml
spec:
  schedule: "*/10 * * * *"
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  startingDeadlineSeconds: 60
```
      </Fragment>
    </Row>

    <Row last terminal>
      <p slot="docs">Suspend and resume CronJobs. Trigger manual runs from existing CronJob template. View Job history and logs.</p>
      <Fragment slot="code">
```bash
$ kubectl patch cronjob nightly-backup \
    -p '{"spec":{"suspend":true}}'
cronjob.batch/nightly-backup patched

$ kubectl patch cronjob nightly-backup \
    -p '{"spec":{"suspend":false}}'
cronjob.batch/nightly-backup patched

$ kubectl create job manual-backup --from=cronjob/nightly-backup
job.batch/manual-backup created
```

```bash
$ kubectl get jobs

db-migrate     1/1           45s        5m
manual-backup  0/1           2m         2m

$ kubectl describe job db-migrate

$ kubectl logs job/db-migrate
Migration completed successfully

$ kubectl get cronjobs
NAME             SCHEDULE      SUSPEND   ACTIVE   LAST SCHEDULE
nightly-backup   0 2 * * *     False     0        12h

$ kubectl get jobs -l app=nightly-backup
```
