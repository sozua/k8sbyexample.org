<Intro>
  <p>Canary deployments release new versions to a small subset of traffic first. If the canary is healthy, gradually increase traffic until full rollout. If problems occur, roll back with minimal impact. Use for: risk mitigation, A/B testing, feature validation, compliance requirements.</p>
</Intro>

    <Row last>
      <p slot="docs">Basic canary with two Deployments sharing a Service. Both have the same app label so the Service routes to both. Adjust replica counts to control traffic split (9 stable + 1 canary = 10% canary traffic).</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-stable
spec:
  replicas: 9
  selector:
    matchLabels:
      app: my-app
      version: stable
  template:
    metadata:
      labels:
        app: my-app
        version: stable
    spec:
      containers:
        - name: app
          image: my-app:v1.0.0
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-canary
spec:
  replicas: 1
  selector:
    matchLabels:
      app: my-app
      version: canary
  template:
    metadata:
      labels:
        app: my-app
        version: canary
    spec:
      containers:
        - name: app
          image: my-app:v1.1.0
```

    <Row last>
      <p slot="docs">Ingress-based canary with nginx-ingress annotations. The <code>canary-weight</code> annotation sends a percentage of traffic to the canary backend. More precise than replica-based splitting.</p>
      <Fragment slot="code">
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-stable
spec:
  ingressClassName: nginx
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: app-stable
                port:
                  number: 80
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-canary
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-weight: "10"
spec:
  ingressClassName: nginx
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: app-canary
                port:
                  number: 80
```
      </Fragment>

    <Row last>
      <p slot="docs">Header-based canary routing. Only requests with specific headers go to canary. Useful for internal testing before public rollout. Combine with weight for staged rollout.</p>
      <Fragment slot="code">
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-canary-header
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-by-header: "X-Canary"
    nginx.ingress.kubernetes.io/canary-by-header-value: "true"
spec:
  ingressClassName: nginx
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: app-canary
                port:
                  number: 80
```

    <FileHeader filename="canary-analysis.yaml" />
    <Row last>
      <p slot="docs">Argo Rollouts provides automated canary analysis. Define metrics to check (error rate, latency) and thresholds. The rollout automatically progresses or rolls back based on analysis results.</p>
      <Fragment slot="code">
```yaml
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: my-app
spec:
  replicas: 10
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: app
          image: my-app:v1.1.0
  strategy:
    canary:
      steps:
        - setWeight: 10
        - pause: {duration: 5m}
        - setWeight: 30
        - pause: {duration: 5m}
        - setWeight: 50
        - pause: {duration: 5m}
      analysis:
        templates:
          - templateName: success-rate
        startingStep: 1
```
      </Fragment>
    </Row>

    <FileHeader filename="analysis-template.yaml" />
    <Row last>
      <p slot="docs">AnalysisTemplate defines how to measure canary health. Query Prometheus for error rates, compare against thresholds. If the analysis fails, the rollout automatically aborts.</p>
      <Fragment slot="code">
```yaml
apiVersion: argoproj.io/v1alpha1
kind: AnalysisTemplate
metadata:
  name: success-rate
spec:
  metrics:
    - name: success-rate
      interval: 1m
      successCondition: result[0] >= 0.95
      failureLimit: 3
      provider:
        prometheus:
          address: http://prometheus.monitoring.svc:9090
          query: |
            sum(rate(http_requests_total{
              app="my-app",
              status=~"2.."
            }[5m])) /
            sum(rate(http_requests_total{
              app="my-app"
            }[5m]))
```
