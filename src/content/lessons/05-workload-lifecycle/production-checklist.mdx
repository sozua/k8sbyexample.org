<Intro>
  <p>A Deployment that works in dev often breaks in prod. This checklist covers what you need: resource constraints, health checks, graceful shutdown, and high availability.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="1-resources.yaml" />
    <Row>
      <p slot="docs"><strong>Set resource requests and limits.</strong> Without requests, the scheduler can't make good decisions. Your Pod might land on an overloaded node. Without limits, a memory leak takes down the entire node.</p>
      <Fragment slot="code">
```yaml
resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    cpu: 500m
    memory: 256Mi
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>Set memory limit equal to request.</strong> This creates Guaranteed QoS class and makes scheduling predictable. CPU can burst (set limit higher than request), but memory should match to avoid OOMKill surprises when pods use more than requested.</p>
      <Fragment slot="code">
```yaml
resources:
  requests:
    cpu: 100m
    memory: 512Mi
  limits:
    cpu: 1
    memory: 512Mi
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="2-probes.yaml" />
    <Row>
      <p slot="docs"><strong>Configure readiness probe.</strong> Without it, traffic hits Pods before they're ready. During rolling updates, users see errors. The probe should check if your app can actually serve requests, not just if the process is alive.</p>
      <Fragment slot="code">
```yaml
readinessProbe:
  httpGet:
    path: /health/ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
  failureThreshold: 3
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>Configure liveness probe.</strong> Restarts stuck processes. Be careful: if your liveness check is too aggressive, you'll restart healthy Pods under load. Make it simpler than readiness - just "is the process responding at all?"</p>
      <Fragment slot="code">
```yaml
livenessProbe:
  httpGet:
    path: /health/live
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10
  failureThreshold: 3
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="3-shutdown.yaml" />
    <Row>
      <p slot="docs"><strong>Handle SIGTERM.</strong> Kubernetes sends SIGTERM, waits <code>terminationGracePeriodSeconds</code>, then SIGKILL. Your app must catch SIGTERM and finish in-flight requests. 30s default is often not enough for long-running operations.</p>
      <Fragment slot="code">
```yaml
spec:
  terminationGracePeriodSeconds: 60
  containers:
    - name: api
      lifecycle:
        preStop:
          exec:
            command: ["/bin/sh", "-c", "sleep 5"]
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>The preStop sleep trick:</strong> Load balancers take a few seconds to remove endpoints. Without the sleep, requests hit terminating Pods. The sleep gives the LB time to update, then your app handles SIGTERM cleanly.</p>
      <Fragment slot="code">
```javascript
process.on('SIGTERM', async () => {
  console.log('SIGTERM received, finishing requests...');
  server.close(async () => {
    await db.disconnect();
    process.exit(0);
  });
});
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="4-replicas.yaml" />
    <Row last>
      <p slot="docs"><strong>Run multiple replicas.</strong> Single replica = single point of failure. During node maintenance, deploys, or crashes - you're down. Minimum 2 for any service that matters. 3+ for critical paths.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: api
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="5-anti-affinity.yaml" />
    <Row last>
      <p slot="docs"><strong>Spread Pods across nodes.</strong> 3 replicas on 1 node = still a single point of failure. Anti-affinity ensures Pods land on different nodes. Use <code>preferredDuringScheduling</code> so Pods can still schedule if nodes are limited.</p>
      <Fragment slot="code">
```yaml
spec:
  template:
    spec:
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: api
                topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="6-pdb.yaml" />
    <Row last>
      <p slot="docs"><strong>Set Pod Disruption Budget.</strong> Without PDB, <code>kubectl drain</code> can evict all your Pods at once during maintenance. PDB guarantees minimum availability. <code>maxUnavailable: 1</code> means only 1 Pod can be down at a time.</p>
      <Fragment slot="code">
```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: api-pdb
spec:
  maxUnavailable: 1
  selector:
    matchLabels:
      app: api
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="7-security.yaml" />
    <Row>
      <p slot="docs"><strong>Drop root privileges.</strong> Running as root inside the container is unnecessary for most apps and dangerous if compromised. Set <code>runAsNonRoot: true</code> and specify a user ID.</p>
      <Fragment slot="code">
```yaml
spec:
  template:
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        fsGroup: 1000
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>Make filesystem read-only.</strong> Prevents attackers from dropping malware. Use <code>emptyDir</code> for directories that need writes (tmp, cache). Drop all capabilities your app doesn't need.</p>
      <Fragment slot="code">
```yaml
      containers:
        - name: api
          securityContext:
            readOnlyRootFilesystem: true
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: tmp
              mountPath: /tmp
      volumes:
        - name: tmp
          emptyDir: {}
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="8-rolling-update.yaml" />
    <Row last>
      <p slot="docs"><strong>Configure rolling update strategy.</strong> Defaults are conservative. <code>maxSurge</code> = extra Pods during update (speed). <code>maxUnavailable</code> = Pods that can be down (capacity). For zero-downtime: <code>maxUnavailable: 0</code>.</p>
      <Fragment slot="code">
```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="9-labels.yaml" />
    <Row last>
      <p slot="docs"><strong>Add operational labels.</strong> You'll need these when everything's on fire at 3am. <code>app</code> for selecting resources, <code>version</code> for rollback decisions, <code>team</code> for finding who owns it.</p>
      <Fragment slot="code">
```yaml
metadata:
  name: api
  labels:
    app: api
    app.kubernetes.io/name: api
    app.kubernetes.io/version: "2.1.0"
    app.kubernetes.io/component: backend
    team: platform
    environment: production
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="10-complete.yaml" />
    <Row last>
      <p slot="docs"><strong>Full production-ready Deployment.</strong> All the pieces together. This survives node failures, deploys cleanly, shuts down gracefully, and doesn't run as root.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
  labels:
    app: api
    team: platform
spec:
  replicas: 3
  strategy:
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      terminationGracePeriodSeconds: 60
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: api
                topologyKey: kubernetes.io/hostname
      containers:
        - name: api
          image: api:2.1.0
          ports:
            - containerPort: 8080
          resources:
            requests:
              cpu: 100m
              memory: 256Mi
            limits:
              cpu: 500m
              memory: 256Mi
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 5
          livenessProbe:
            httpGet:
              path: /health/live
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 10
          securityContext:
            readOnlyRootFilesystem: true
            allowPrivilegeEscalation: false
          lifecycle:
            preStop:
              exec:
                command: ["/bin/sh", "-c", "sleep 5"]
```
      </Fragment>
    </Row>
