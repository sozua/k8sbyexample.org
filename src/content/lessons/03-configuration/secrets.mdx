<Intro>
  <p>Secrets store sensitive data: passwords, tokens, keys. Base64-encoded by default (not encrypted!). In production, enable encryption at rest and consider external secret managers like Vault or AWS Secrets Manager.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="secret.yaml" />
    <Row last>
      <p slot="docs">Secrets use the core <code>v1</code> API. Values in <code>data</code> must be base64 encoded. Use <code>echo -n "password" | base64</code> to encode.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
data:
  DB_PASSWORD: cGFzc3dvcmQ=
  API_KEY: c2VjcmV0LWtleQ==
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="secret-stringdata.yaml" />
    <Row last>
      <p slot="docs">Use <code>stringData</code> to avoid manual base64 encoding since Kubernetes encodes it automatically. You can mix <code>data</code> and <code>stringData</code> in the same Secret.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
stringData:
  DB_PASSWORD: "my-actual-password"
  API_KEY: "my-api-key"
  config.yaml: |
    database:
      host: postgres
      port: 5432
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="secret-types.yaml" />
    <Row last>
      <p slot="docs">Secret types provide structure and validation. <code>Opaque</code> is generic. Built-in types include TLS, docker-registry, basic-auth, and ssh-auth with required keys.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
type: kubernetes.io/tls
metadata:
  name: tls-secret
data:
  tls.crt: <base64-cert>
  tls.key: <base64-key>
---
apiVersion: v1
kind: Secret
type: kubernetes.io/basic-auth
stringData:
  username: admin
  password: secret123
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-secret-env.yaml" />
    <Row last>
      <p slot="docs">Inject secrets as environment variables. Same pattern as ConfigMaps. Use <code>optional: true</code> to allow Pod startup if secret doesn't exist.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      envFrom:
        - secretRef:
            name: app-secrets
            optional: true
      env:
        - name: PASSWORD
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: DB_PASSWORD
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="pod-secret-volume.yaml" />
    <Row last>
      <p slot="docs">Mount secrets as files. Files are stored in tmpfs (RAM, not disk). Set proper permissions with <code>defaultMode</code>. Use <code>items</code> to mount specific keys.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      volumeMounts:
        - name: certs
          mountPath: /etc/ssl/certs
          readOnly: true
  volumes:
    - name: certs
      secret:
        secretName: tls-certs
        defaultMode: 0400
        items:
          - key: tls.crt
            path: server.crt
```
      </Fragment>
    </Row>
  </tbody>
</table>

      <p slot="docs">Docker registry secrets authenticate image pulls from private registries. Create with kubectl or declaratively.</p>
      <Fragment slot="code">
```bash
$ kubectl create secret docker-registry regcred \
    --docker-server=ghcr.io \
    --docker-username=user \
    --docker-password=token
secret/regcred created
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Reference in Pod spec with <code>imagePullSecrets</code>. Can also be attached to a ServiceAccount for automatic use.</p>
      <Fragment slot="code">
```yaml
spec:
  imagePullSecrets:
    - name: regcred
  containers:
    - name: app
      image: ghcr.io/org/private-app:v1
```

    <FileHeader filename="encryption-config.yaml" />
    <Row last>
      <p slot="docs">Encryption at rest protects Secrets in etcd. Without it, Secrets are only base64-encoded (easily decoded). Configure EncryptionConfiguration on the API server.</p>
      <Fragment slot="code">
```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <base64-32-byte-key>
      - identity: {}
```
      </Fragment>
    </Row>
  </tbody>

      <p slot="docs">Best practices: use RBAC to restrict Secret access, avoid committing to Git (use sealed-secrets), rotate credentials regularly. Secrets are namespaced.</p>
      <Fragment slot="code">
```bash
$ kubectl get secret app-secrets -o yaml
apiVersion: v1
kind: Secret
data:
  DB_PASSWORD: cGFzc3dvcmQ=
...

$ kubectl get secret app-secrets \
    -o jsonpath='{.data.DB_PASSWORD}' | base64 -d
password

$ kubectl get secrets --all-namespaces
NAMESPACE   NAME          TYPE     DATA   AGE
default     app-secrets   Opaque   2      5m
kube-system coredns       Opaque   0      30d
```
