<Intro>
  <p>Namespaces partition a cluster into virtual sub-clusters. They provide scope for names and are the basis for resource quotas and RBAC policies.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="namespace.yaml" />
    <Row>
      <p slot="docs">A Namespace is a core Kubernetes resource (<code>v1</code> API).</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Namespace
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs">The <code>name</code> must be unique cluster-wide. Use lowercase, numbers, and hyphens only.</p>
      <Fragment slot="code">
```yaml
metadata:
  name: my-app
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Labels help organize and select namespaces. Common patterns: environment, team, cost-center.</p>
      <Fragment slot="code">
```yaml
  labels:
    environment: production
    team: platform
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <TerminalHeader cmd="kubectl get namespaces" />
    <Row last terminal>
      <p slot="docs">Built-in namespaces: <code>default</code> (your resources if unspecified), <code>kube-system</code> (control plane), <code>kube-public</code> (readable by all).</p>
      <Fragment slot="code">
```bash
$ kubectl get namespaces
NAME              STATUS   AGE
default           Active   45d
kube-system       Active   45d
kube-public       Active   45d
kube-node-lease   Active   45d
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod.yaml" />
    <Row>
      <p slot="docs">Within the same namespace, reference services by name only. Kubernetes DNS resolves it automatically.</p>
      <Fragment slot="code">
```yaml
env:
  - name: API_URL
    value: "http://api:8080"
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs">Cross-namespace references use <code>service.namespace.svc</code> format.</p>
      <Fragment slot="code">
```yaml
  - name: REDIS_URL
    value: "redis://redis.cache.svc:6379"
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Full FQDN includes <code>.cluster.local</code>. Usually only needed for edge cases.</p>
      <Fragment slot="code">
```yaml
  - name: DB_HOST
    value: "postgres.db.svc.cluster.local"
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="resourcequota.yaml" />
    <Row>
      <p slot="docs">ResourceQuotas limit total resource consumption per namespace. Prevents one team from consuming all cluster resources.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: my-app
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><code>spec.hard</code> defines the limits. Constrain CPU, memory, storage, and object counts.</p>
      <Fragment slot="code">
```yaml
spec:
  hard:
    requests.cpu: "10"
    requests.memory: 20Gi
    limits.cpu: "20"
    limits.memory: 40Gi
    pods: "50"
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="limitrange.yaml" />
    <Row>
      <p slot="docs">LimitRanges set default and max/min resource limits per container.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: default-limits
spec:
  limits:
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs"><code>default</code> sets limits when not specified.</p>
      <Fragment slot="code">
```yaml
    - default:
        cpu: "500m"
        memory: "512Mi"
```
      </Fragment>
    </Row>
  </tbody>
  <tbody>
    <Row last>
      <p slot="docs"><code>defaultRequest</code> sets requests.</p>
      <Fragment slot="code">
```yaml
      defaultRequest:
        cpu: "100m"
        memory: "128Mi"
      type: Container
```
      </Fragment>
    </Row>
  </tbody>
</table>
