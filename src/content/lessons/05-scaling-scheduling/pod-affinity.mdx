<Intro>
  <p>Pod affinity schedules Pods on nodes where specific Pods are already running. Use for: co-locating related services, reducing network latency, data locality.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod-affinity.yaml" />
    <Row last>
      <p slot="docs">Pod affinity is defined in <code>spec.affinity.podAffinity</code>. <code>labelSelector</code> matches target Pods. <code>topologyKey</code> defines the scope (same node, zone, etc.).</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: cache
          topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod-affinity-types.yaml" />
    <Row last>
      <p slot="docs">First example: <code>required</code> is a hard constraint, so the Pod won't schedule if unsatisfied. Second example: <code>preferred</code> is soft, so the scheduler tries but doesn't guarantee. Weight determines preference strength (higher = stronger).</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: cache
          topologyKey: kubernetes.io/hostname
---
spec:
  affinity:
    podAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: cache
            topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="topology-keys.yaml" />
    <Row last>
      <p slot="docs"><code>topologyKey</code> defines the scope. <code>kubernetes.io/hostname</code> = same node, <code>topology.kubernetes.io/zone</code> = same AZ, <code>topology.kubernetes.io/region</code> = same region. Custom keys for rack-aware scheduling.</p>
      <Fragment slot="code">
```yaml
topologyKey: kubernetes.io/hostname

topologyKey: topology.kubernetes.io/zone

topologyKey: topology.kubernetes.io/region

topologyKey: rack.example.com/rack-id
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="pod-affinity-expressions.yaml" />
    <Row last>
      <p slot="docs">Use <code>matchExpressions</code> for complex label matching. Supports operators: <code>In</code>, <code>NotIn</code>, <code>Exists</code>, <code>DoesNotExist</code>. Multiple expressions use AND logic.</p>
      <Fragment slot="code">
```yaml
podAffinity:
  requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchExpressions:
          - key: app
            operator: In
            values:
              - cache
              - queue
          - key: environment
            operator: In
            values:
              - production
      topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-affinity-namespace.yaml" />
    <Row last>
      <p slot="docs"><code>namespaceSelector</code> matches Pods across namespaces. By default, affinity only considers Pods in the same namespace. Use for cross-namespace dependencies.</p>
      <Fragment slot="code">
```yaml
podAffinity:
  requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchLabels:
          app: cache
      namespaceSelector:
        matchLabels:
          team: platform
      topologyKey: kubernetes.io/hostname
---
    - labelSelector:
        matchLabels:
          app: cache
      namespaces:
        - shared-services
      topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>

    <FileHeader filename="pod-combined-affinity.yaml" />
    <Row last>
      <p slot="docs">Combine affinity with anti-affinity for complex placement. Co-locate with dependencies but spread across nodes. Common pattern for stateful applications with their caches.</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: redis
            topologyKey: kubernetes.io/hostname
    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: my-app
            topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>

    <Row last terminal>
      <p slot="docs">Debug pod affinity issues by checking scheduler events. Pending Pods show why no node was selected. Verify target Pods exist and have matching labels.</p>
      <Fragment slot="code">
```bash
$ kubectl describe pod my-app
Events:
  Type     Reason            Age   Message
  Warning  FailedScheduling  10s   0/3 nodes available:
    3 node(s) didn't match pod affinity rules

$ kubectl get pods -l app=cache --show-labels
NAME      READY   STATUS    LABELS
cache-1   1/1     Running   app=cache,env=prod

$ kubectl get pods -l app=cache -o wide
NAME      READY   NODE
cache-1   1/1     node-1

$ kubectl get pod my-app -o jsonpath='{.spec.affinity}' | jq
```
