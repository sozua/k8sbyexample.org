<Intro>
  <p>HPA scales Pods based on CPU, memory, or custom metrics. Requires metrics-server in the cluster. Adjusts replicas to maintain target utilization automatically.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="hpa.yaml" />
    <Row last>
      <p slot="docs">HPA uses the <code>autoscaling/v2</code> API. <code>scaleTargetRef</code> points to the Deployment to scale. HPA adjusts replicas between min and max based on metrics.</p>
      <Fragment slot="code">
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: my-app
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="pod-resources.yaml" />
    <Row last>
      <p slot="docs">HPA calculates utilization as current/request. Requires resource requests to be defined. Without requests, HPA cannot determine utilization percentage.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      resources:
        requests:
          cpu: 200m
          memory: 256Mi
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="hpa-multi-metric.yaml" />
    <Row last>
      <p slot="docs">Combine CPU and memory metrics. HPA takes the max of calculated replicas from all metrics. Good for workloads that are both CPU and memory bound.</p>
      <Fragment slot="code">
```yaml
spec:
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="hpa-behavior.yaml" />
    <Row last>
      <p slot="docs">Control scaling behavior: scale up fast, down slow. <code>stabilizationWindowSeconds</code> prevents flapping during traffic spikes. Policies control scale rate per time period.</p>
      <Fragment slot="code">
```yaml
spec:
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 10
          periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
        - type: Percent
          value: 100
          periodSeconds: 15
        - type: Pods
          value: 4
          periodSeconds: 15
      selectPolicy: Max
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="hpa-custom.yaml" />
    <Row last>
      <p slot="docs">Custom metrics from Prometheus or other sources. Requires metrics adapter (prometheus-adapter, KEDA). Scale on queue depth, requests per second, or any application metric.</p>
      <Fragment slot="code">
```yaml
spec:
  metrics:
    - type: Pods
      pods:
        metric:
          name: requests_per_second
        target:
          type: AverageValue
          averageValue: 1000
    - type: Object
      object:
        metric:
          name: queue_depth
        describedObject:
          apiVersion: v1
          kind: Service
          name: rabbitmq
        target:
          type: Value
          value: 100
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="hpa-external.yaml" />
    <Row last>
      <p slot="docs">External metrics come from outside the cluster (cloud monitoring, SaaS). Scale based on SQS queue length, Pub/Sub backlog, or any external data source. Requires external metrics provider like KEDA.</p>
      <Fragment slot="code">
```yaml
spec:
  metrics:
    - type: External
      external:
        metric:
          name: sqs_queue_messages
          selector:
            matchLabels:
              queue: orders
        target:
          type: AverageValue
          averageValue: 10
```
      </Fragment>
    </Row>

    <FileHeader filename="hpa-targets.yaml" />
    <Row last>
      <p slot="docs">HPA works with Deployments, StatefulSets, and ReplicaSets. Cannot scale DaemonSets (1 per node by design). It conflicts with manual scaling because HPA overwrites manual replica changes.</p>
      <Fragment slot="code">
```yaml
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: my-app
---
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: StatefulSet
    name: postgres
```
      </Fragment>
    </Row>
  </tbody>
