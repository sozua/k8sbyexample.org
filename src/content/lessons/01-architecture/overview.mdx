<Intro>
  <p>Kubernetes orchestrates containers across a cluster of machines. This guide shows how the core components fit together: Cluster, Nodes, Pods, Deployments, and Services.</p>
</Intro>

    <FileHeader filename="cluster-overview.txt" />
    <Row last>
      <p slot="docs">A <strong>Cluster</strong> is a set of machines (nodes) running Kubernetes. The Control Plane manages the cluster, worker nodes run your applications.</p>
      <Fragment slot="code">
```
+-----------------------------------------------------------+
|                         CLUSTER                           |
|                                                           |
|  +---------------+      +---------------------------+     |
|  | Control Plane |      |       Worker Nodes        |     |
|  |               |      |                           |     |
|  |  - API Server |----->|  +--------+   +--------+  |     |
|  |  - Scheduler  |      |  | Node 1 |   | Node 2 |  |     |
|  |  - etcd       |      |  | (Pods) |   | (Pods) |  |     |
|  |               |      |  +--------+   +--------+  |     |
|  +---------------+      +---------------------------+     |
|                                                           |
+-----------------------------------------------------------+
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="node.txt" />
    <Row last>
      <p slot="docs">A <strong>Node</strong> is a machine (physical or virtual) in the cluster. Each node runs kubelet (agent), kube-proxy (networking), and a container runtime. Nodes host Pods.</p>
      <Fragment slot="code">
```
+-----------------------------------------+
|                  NODE                   |
|                                         |
|  +-----------------------------------+  |
|  | kubelet          (talks to API)   |  |
|  | kube-proxy       (networking)     |  |
|  | container runtime (runs pods)     |  |
|  +-----------------------------------+  |
|                                         |
|  +---------+ +---------+ +---------+    |
|  |  Pod A  | |  Pod B  | |  Pod C  |    |
|  +---------+ +---------+ +---------+    |
|                                         |
+-----------------------------------------+
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod.txt" />
    <Row last>
      <p slot="docs">A <strong>Pod</strong> is the smallest deployable unit. It wraps one or more containers that share network (same IP) and storage. Containers in a Pod communicate via localhost.</p>
      <Fragment slot="code">
```
+---------------------------------------+
|                 POD                   |
|            IP: 10.244.1.5             |
|                                       |
|  +-------------+   +-------------+    |
|  |  Container  |   |  Container  |    |
|  |    nginx    |   |   sidecar   |    |
|  |     :80     |   |    :9090    |    |
|  +-------------+   +-------------+    |
|         ^                 ^           |
|         +--- localhost ---+           |
|                                       |
|  +----------------------------------+ |
|  |          Shared Volume           | |
|  +----------------------------------+ |
+---------------------------------------+
```
      </Fragment>
    </Row>
  </tbody>
</table>

      <p slot="docs"><strong>Deployment</strong> manages <strong>ReplicaSets</strong>, which ensure N copies of a Pod run. You define desired state, Kubernetes maintains it. Deployments handle rolling updates.</p>
      <Fragment slot="code">

```
+-----------------------------------------------+
|                  DEPLOYMENT                   |
|                  replicas: 3                  |
|                                               |
|  +-----------------------------------------+  |

|  |                                         |  |
|  |  +---------+ +---------+ +---------+    |  |
|  |  |   Pod   | |   Pod   | |   Pod   |    |  |
|  |  |  nginx  | |  nginx  | |  nginx  |    |  |
|  |  +---------+ +---------+ +---------+    |  |
|  |                                         |  |
|  +-----------------------------------------+  |
|                                               |
+-----------------------------------------------+
```

    <FileHeader filename="service.txt" />
    <Row last>
      <p slot="docs">A <strong>Service</strong> provides a stable IP and DNS name to access Pods. Pods are ephemeral (they come and go), but Services give a fixed endpoint. Load balances across matching Pods.</p>
      <Fragment slot="code">
```
                +-----------------+
                |     SERVICE     |
 requests ----->|  nginx-service  |
                |   10.96.0.100   |
                +--------+--------+
                         |
         +---------------+---------------+
         |               |               |
         v               v               v
   +------------+   +------------+   +------------+
   |     Pod    |   |     Pod    |   |     Pod    |
   |    nginx   |   |    nginx   |   |    nginx   |
   | 10.244.1.5 |   | 10.244.2.3 |   | 10.244.3.7 |
   +------------+   +------------+   +------------+
```
      </Fragment>

      <p slot="docs"><strong>Namespaces</strong> divide a cluster into virtual clusters. Use them to separate teams, environments (dev/prod), or projects. Resources in different namespaces are isolated by default.</p>
      <Fragment slot="code">
```
+-------------------------------------------------+
|                    CLUSTER                      |
|                                                 |
|  +---------------+     +---------------+        |
|  |  namespace:   |     |  namespace:   |        |
|  |     dev       |     |     prod      |        |
|  |               |     |               |        |
|  | +-----------+ |     | +-----------+ |  same  |
|  | | nginx-svc | |     | | nginx-svc | |  names |
|  | | nginx-pod | |     | | nginx-pod | |        |
|  | +-----------+ |     | +-----------+ |        |
|  |               |     |               |        |
|  +---------------+     +---------------+        |
|                                                 |
+-------------------------------------------------+
```

      <p slot="docs"><strong>Labels</strong> are key-value tags on resources. <strong>Selectors</strong> find resources by labels. This is how Services find Pods, and how you organize resources.</p>
      <Fragment slot="code">
```
    Service selector: app=nginx
                      |
        +-------------+-------------+
        |             |             |
        v             v             v
  +-----------+ +-----------+ +-----------+
  |    Pod    | |    Pod    | |    Pod    |
  | app=nginx | | app=nginx | | app=redis |
  +-----------+ +-----------+ +-----------+
       [x]           [x]       [ ] not selected
```

    <Row last>
      <p slot="docs"><strong>ConfigMap</strong> stores configuration (env vars, config files). <strong>Secret</strong> stores sensitive data (passwords, tokens). Both inject data into Pods without hardcoding.</p>
      <Fragment slot="code">
```
+----------------+     +----------------+
|   ConfigMap    |     |     Secret     |
|                |     |                |
| DB_HOST=mysql  |     | DB_PASS=****   |
| LOG_LEVEL=info |     | API_KEY=****   |
+-------+--------+     +-------+--------+
        |                      |
        +----------+-----------+
                   |
                   v
            +-------------+
            |     Pod     |
            |             |
            | DB_HOST     | <- ConfigMap
            | DB_PASS     | <- Secret
            +-------------+
```
      </Fragment>
    </Row>
