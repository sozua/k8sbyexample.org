<Intro>
  <p>Deployments gerenciam Pods via ReplicaSets. A hierarquia é: Deployment → ReplicaSet → Pods. Deployments adicionam self-healing, scaling, rolling updates e rollbacks sobre ReplicaSets.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="deployment.yaml" />
    <Row>
      <p slot="docs">Deployments usam a API <code>apps/v1</code>. O selector vincula o Deployment aos seus Pods.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app.kubernetes.io/name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app.kubernetes.io/name: my-app
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">O template do Pod define como cada réplica se parece. Labels no template devem corresponder ao selector.</p>
      <Fragment slot="code">
```yaml
  template:
    metadata:
      labels:
        app.kubernetes.io/name: my-app
    spec:
      containers:
        - name: app
          image: my-app:v1.2.0
          ports:
            - name: http
              containerPort: 8080
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="rolling-update-strategy.yaml" />
    <Row>
      <p slot="docs">Duas estratégias de update: <code>RollingUpdate</code> (padrão) substitui Pods gradualmente; <code>Recreate</code> mata todos os Pods antes de criar novos.</p>
      <Fragment slot="code">
```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 0
      maxSurge: 1
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><code>minReadySeconds</code> atrasa a marcação de Pods como ready. <code>revisionHistoryLimit</code> controla quantos ReplicaSets antigos manter para rollback.</p>
      <Fragment slot="code">
```yaml
  replicas: 3
  minReadySeconds: 10
  revisionHistoryLimit: 5
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <TerminalHeader cmd="kubectl rollout undo deployment/my-app" />
    <Row last terminal>
      <p slot="docs">Rollbacks são rápidos porque ReplicaSets antigos ainda existem. Kubernetes apenas escala eles para cima e para baixo.</p>
      <Fragment slot="code">
```bash
$ kubectl rollout undo deployment/my-app
deployment.apps/my-app rolled back

$ kubectl rollout undo deployment/my-app --to-revision=2
deployment.apps/my-app rolled back to revision 2
```

    </Row>

    <Row last terminal>
      <p slot="docs">Pause e resume rollouts para deploys estilo canary. Enquanto pausado, você pode testar novos Pods antes de completar o update.</p>
      <Fragment slot="code">
```bash
$ kubectl set image deployment/my-app app=my-app:v2.0.0
deployment.apps/my-app image updated

$ kubectl rollout pause deployment/my-app
deployment.apps/my-app paused

$ kubectl rollout resume deployment/my-app
deployment.apps/my-app resumed
```
