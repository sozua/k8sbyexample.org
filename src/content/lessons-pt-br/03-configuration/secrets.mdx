<Intro>
  <p>Secrets armazenam dados sensíveis: senhas, tokens, chaves. Codificados em base64 por padrão (não criptografados!). Em produção, habilite encryption at rest e considere gerenciadores externos como Vault ou AWS Secrets Manager.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="secret.yaml" />
    <Row last>
      <p slot="docs">Secrets usam a API core <code>v1</code>. Valores em <code>data</code> devem ser codificados em base64. Use <code>echo -n "password" | base64</code> para codificar.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
data:
  DB_PASSWORD: cGFzc3dvcmQ=
  API_KEY: c2VjcmV0LWtleQ==
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <Row last>
      <p slot="docs">Use <code>stringData</code> para evitar codificação base64 manual - Kubernetes codifica automaticamente. Você pode misturar <code>data</code> e <code>stringData</code> no mesmo Secret.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
stringData:
  DB_PASSWORD: "my-actual-password"
  API_KEY: "my-api-key"
  config.yaml: |
    database:
      host: postgres
      port: 5432
```

    <FileHeader filename="secret-types.yaml" />
    <Row last>
      <p slot="docs">Tipos de Secret fornecem estrutura e validação. <code>Opaque</code> é genérico. Tipos built-in incluem TLS, docker-registry, basic-auth e ssh-auth com chaves obrigatórias.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Secret
type: kubernetes.io/tls
metadata:
  name: tls-secret
data:
  tls.crt: <base64-cert>
  tls.key: <base64-key>
---
apiVersion: v1
kind: Secret
type: kubernetes.io/basic-auth
stringData:
  username: admin
  password: secret123
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-secret-env.yaml" />
    <Row last>
      <p slot="docs">Injete secrets como variáveis de ambiente. Mesmo padrão de ConfigMaps. Use <code>optional: true</code> para permitir startup do Pod se o secret não existir.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      envFrom:
        - secretRef:
            name: app-secrets
            optional: true
      env:
        - name: PASSWORD
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: DB_PASSWORD
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-secret-volume.yaml" />
    <Row last>
      <p slot="docs">Monte secrets como arquivos. Arquivos são armazenados em tmpfs (RAM, não disco). Defina permissões apropriadas com <code>defaultMode</code>. Use <code>items</code> para montar chaves específicas.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      volumeMounts:
        - name: certs
          mountPath: /etc/ssl/certs
          readOnly: true
  volumes:
    - name: certs
      secret:
        secretName: tls-certs
        defaultMode: 0400
        items:
          - key: tls.crt
            path: server.crt
```
      </Fragment>
    </Row>
  </tbody>

    <Row>
      <p slot="docs">Secrets de docker registry autenticam pulls de imagens de registries privados. Crie com kubectl ou declarativamente.</p>
      <Fragment slot="code">
```bash
$ kubectl create secret docker-registry regcred \
    --docker-server=ghcr.io \
    --docker-username=user \
    --docker-password=token
secret/regcred created
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Referencie no spec do Pod com <code>imagePullSecrets</code>. Também pode ser anexado a uma ServiceAccount para uso automático.</p>
      <Fragment slot="code">
```yaml
spec:
  imagePullSecrets:
    - name: regcred
  containers:
    - name: app
      image: ghcr.io/org/private-app:v1
```
      </Fragment>
    </Row>

    <FileHeader filename="encryption-config.yaml" />
    <Row last>
      <p slot="docs">Encryption at rest protege Secrets no etcd. Sem ela, Secrets são apenas base64-encoded (facilmente decodificados). Configure EncryptionConfiguration no API server.</p>
      <Fragment slot="code">
```yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
  - resources:
      - secrets
    providers:
      - aescbc:
          keys:
            - name: key1
              secret: <base64-32-byte-key>
      - identity: {}
```
      </Fragment>
    </Row>

      <p slot="docs">Boas práticas: use RBAC para restringir acesso a Secrets, evite commit no Git (use sealed-secrets), rotacione credenciais regularmente. Secrets são namespaced.</p>
      <Fragment slot="code">
```bash
$ kubectl get secret app-secrets -o yaml
apiVersion: v1
kind: Secret
data:
  DB_PASSWORD: cGFzc3dvcmQ=
...

$ kubectl get secret app-secrets \
    -o jsonpath='{.data.DB_PASSWORD}' | base64 -d
password

$ kubectl get secrets --all-namespaces
NAMESPACE   NAME          TYPE     DATA   AGE
default     app-secrets   Opaque   2      5m
kube-system coredns       Opaque   0      30d
```
