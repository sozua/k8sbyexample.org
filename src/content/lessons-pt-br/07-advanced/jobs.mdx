<Intro>
  <p>Jobs executam uma tarefa até completar. Diferente de Deployments que rodam indefinidamente, Jobs garantem que um número especificado de Pods complete com sucesso. Use para: migrações, processamento batch, backups, tarefas únicas.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="job.yaml" />
    <Row last>
      <p slot="docs">Job executa Pods até completar com sucesso. <code>restartPolicy</code> deve ser <code>Never</code> ou <code>OnFailure</code> (obrigatório). <code>backoffLimit: 3</code> tenta 3 vezes antes de marcar como falho.</p>
      <Fragment slot="code">
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migrate
spec:
  template:
    spec:
      containers:
        - name: migrate
          image: my-app:v1
          command: ["python", "migrate.py"]
      restartPolicy: Never
  backoffLimit: 3
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="job-parallel.yaml" />
    <Row last>
      <p slot="docs">Modos de completion de Job: <code>NonIndexed</code> (padrão) executa N Pods idênticos. <code>Indexed</code> atribui a cada Pod um índice único (0 a completions-1) via variável de ambiente <code>JOB_COMPLETION_INDEX</code> para particionamento de trabalho.</p>
      <Fragment slot="code">
```yaml
spec:
  completions: 10
  parallelism: 3
  completionMode: Indexed
  template:
    spec:
      containers:
        - name: worker
          image: worker:v1
          command: ["./process-partition.sh"]
      restartPolicy: Never
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <Row last>
      <p slot="docs"><code>backoffLimit: 3</code> tenta então Job falha. <code>activeDeadlineSeconds: 600</code> = deve completar em 10 min. <code>ttlSecondsAfterFinished: 3600</code> = deleta 1 hora depois. <code>OnFailure</code> reinicia container no mesmo Pod; <code>Never</code> cria novo Pod para cada retry.</p>
      <Fragment slot="code">
```yaml
spec:
  backoffLimit: 3
  activeDeadlineSeconds: 600
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: OnFailure
```

      <p slot="docs">Jobs paralelos têm três modos. Primeiro exemplo: contagem fixa de completion (executa 10 total, 3 por vez). Segundo exemplo: fila de trabalho (sem completions = Pods coordenam, feito quando qualquer Pod sai com 0). Terceiro exemplo: Pod único (padrão).</p>
      <Fragment slot="code">
```yaml
spec:
  completions: 10
  parallelism: 3
---
spec:
  parallelism: 5
---
spec:
  completions: 1
  parallelism: 1
```

    <FileHeader filename="cronjob.yaml" />
    <Row last>
      <p slot="docs">CronJobs executam Jobs em um agendamento usando sintaxe cron (minuto hora dia-do-mês mês dia-da-semana). Exemplos de schedule no código. Use <code>concurrencyPolicy</code> para controlar execuções sobrepostas.</p>
      <Fragment slot="code">
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-backup
spec:
  schedule: "0 2 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: backup
              image: backup:v1
          restartPolicy: OnFailure
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="cronjob-policy.yaml" />
    <Row last>
      <p slot="docs"><code>concurrencyPolicy</code>: <code>Allow</code> (padrão) permite Jobs concorrentes, <code>Forbid</code> pula se anterior rodando, <code>Replace</code> mata anterior. <code>successfulJobsHistoryLimit: 3</code> mantém 3 completados. <code>startingDeadlineSeconds: 60</code> deve iniciar dentro de 60s do schedule.</p>
      <Fragment slot="code">
```yaml
spec:
  schedule: "*/10 * * * *"
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  startingDeadlineSeconds: 60
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <TerminalHeader cmd="kubectl create job manual-backup --from=cronjob/nightly-backup" />
    <Row last terminal>
      <p slot="docs">Suspenda e retome CronJobs. Dispare execuções manuais do template de CronJob existente. Veja histórico e logs de Job.</p>
      <Fragment slot="code">
```bash
$ kubectl patch cronjob nightly-backup \
    -p '{"spec":{"suspend":true}}'
cronjob.batch/nightly-backup patched

$ kubectl patch cronjob nightly-backup \
    -p '{"spec":{"suspend":false}}'
cronjob.batch/nightly-backup patched

$ kubectl create job manual-backup --from=cronjob/nightly-backup
job.batch/manual-backup created
```
      </Fragment>
    </Row>

      <p slot="docs">Debug Jobs verificando status do Pod, logs e status de completion. Jobs falhos mostram eventos de backoff. CronJobs mostram tempos agendados vs reais de execução.</p>
      <Fragment slot="code">
```bash
$ kubectl get jobs
NAME           COMPLETIONS   DURATION   AGE
db-migrate     1/1           45s        5m
manual-backup  0/1           2m         2m

$ kubectl describe job db-migrate

$ kubectl logs job/db-migrate
Migration completed successfully

$ kubectl get cronjobs
NAME             SCHEDULE      SUSPEND   ACTIVE   LAST SCHEDULE
nightly-backup   0 2 * * *     False     0        12h

$ kubectl get jobs -l app=nightly-backup
```
