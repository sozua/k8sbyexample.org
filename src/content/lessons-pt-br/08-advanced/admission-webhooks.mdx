<Intro>
  <p>Admission webhooks interceptam requests da API antes dos recursos serem persistidos. ValidatingWebhooks rejeitam recursos inválidos. MutatingWebhooks modificam recursos (injetam sidecars, adicionam labels). Webhooks mal configurados podem bloquear todos os deployments e quebrar clusters.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="validatingwebhook.yaml" />
    <Row>
      <p slot="docs">ValidatingWebhookConfiguration define quando chamar seu webhook. <code>rules</code> especifica quais recursos e operações disparam validação.</p>
      <Fragment slot="code">
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: pod-policy
webhooks:
  - name: pod-policy.example.com
    rules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pods"]
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Configure o endpoint do serviço webhook e TLS. O API server chama este serviço para cada request correspondente.</p>
      <Fragment slot="code">
```yaml
    clientConfig:
      service:
        name: pod-policy-webhook
        namespace: webhook-system
        path: /validate
        port: 443
      caBundle: LS0tLS1CRUd...  # Certificado CA em Base64
    admissionReviewVersions: ["v1"]
    sideEffects: None
    timeoutSeconds: 5
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="mutatingwebhook.yaml" />
    <Row>
      <p slot="docs">MutatingWebhookConfiguration modifica recursos. Usos comuns: injetar sidecars (Istio), adicionar labels padrão, configurar security context. Mutations acontecem antes da validação.</p>
      <Fragment slot="code">
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: MutatingWebhookConfiguration
metadata:
  name: sidecar-injector
webhooks:
  - name: sidecar.example.com
    rules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE"]
        resources: ["pods"]
    namespaceSelector:
      matchLabels:
        sidecar-injection: enabled
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Use <code>namespaceSelector</code> ou <code>objectSelector</code> para limitar escopo. Isso previne o webhook de afetar namespaces do sistema.</p>
      <Fragment slot="code">
```yaml
    namespaceSelector:
      matchExpressions:
        - key: kubernetes.io/metadata.name
          operator: NotIn
          values:
            - kube-system
            - kube-public
    objectSelector:
      matchLabels:
        inject-sidecar: "true"
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="webhook-failurepolicy.yaml" />
    <Row>
      <p slot="docs"><code>failurePolicy</code> controla o que acontece quando o webhook está indisponível. <code>Fail</code>: rejeita requests (seguro mas bloqueia deployments). <code>Ignore</code>: permite requests (arriscado mas não bloqueia).</p>
      <Fragment slot="code">
```yaml
webhooks:
  - name: critical-validation.example.com
    failurePolicy: Fail       # Bloqueia se webhook down
    timeoutSeconds: 10

  - name: optional-mutation.example.com
    failurePolicy: Ignore     # Permite se webhook down
    timeoutSeconds: 5
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><strong>Crítico</strong>: Política <code>Fail</code> com webhooks quebrados bloqueia TODOS os requests correspondentes, incluindo pods do kube-system. Isso pode quebrar seu cluster. Sempre exclua namespaces do sistema.</p>
      <Fragment slot="code">
```yaml
# PERIGOSO: Falha em todos pods, incluindo sistema
rules:
  - resources: ["pods"]
failurePolicy: Fail

# SEGURO: Exclui namespaces do sistema
namespaceSelector:
  matchExpressions:
    - key: kubernetes.io/metadata.name
      operator: NotIn
      values: ["kube-system", "kube-public"]
```
      </Fragment>
    </Row>
  </tbody>

    <TerminalHeader cmd="kubectl delete validatingwebhookconfiguration broken-webhook" />
    <Row>
      <p slot="docs"><strong>Correção de emergência</strong>: Delete a configuração do webhook para desbloquear deployments. Isso remove o webhook completamente até você corrigir e reimplantá-lo.</p>
      <Fragment slot="code">
```bash
# Se webhook está bloqueando todos deployments:
$ kubectl delete validatingwebhookconfiguration broken-webhook
validatingwebhookconfiguration.admissionregistration.k8s.io "broken-webhook" deleted

# Deployments devem funcionar agora
$ kubectl get pods -n kube-system
# Pods iniciando novamente
```
      </Fragment>
    </Row>
    <Row last terminal>
      <p slot="docs">Alternativa: faça patch do webhook para política <code>Ignore</code> temporariamente enquanto corrige o problema subjacente.</p>
      <Fragment slot="code">
```bash
# Temporariamente permitir requests quando webhook falha
$ kubectl patch validatingwebhookconfiguration broken-webhook \
    --type='json' \
    -p='[{"op": "replace", "path": "/webhooks/0/failurePolicy", "value": "Ignore"}]'

# Corrija o serviço webhook, depois restaure política Fail
$ kubectl patch validatingwebhookconfiguration broken-webhook \
    --type='json' \
    -p='[{"op": "replace", "path": "/webhooks/0/failurePolicy", "value": "Fail"}]'
```
      </Fragment>
    </Row>

    <FileHeader filename="webhook-service.yaml" />
    <Row last>
      <p slot="docs">O webhook deve ser altamente disponível. Use múltiplas réplicas, resource limits adequados e PodDisruptionBudget. Um webhook down com política <code>Fail</code> bloqueia deployments.</p>
      <Fragment slot="code">
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: pod-policy-webhook
  namespace: webhook-system
spec:
  replicas: 3                    # HA
  selector:
    matchLabels:
      app: pod-policy-webhook
  template:
    spec:
      affinity:
        podAntiAffinity:         # Distribuir entre nodes
          requiredDuringSchedulingIgnoredDuringExecution:
            - topologyKey: kubernetes.io/hostname
      containers:
        - name: webhook
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
```
      </Fragment>
    </Row>
