<Intro>
  <p>Kubernetes executa CoreDNS para resolução de nomes interna. Todo Service ganha um registro DNS A automaticamente. Pods resolvem nomes de Service para ClusterIPs sem hardcodar endereços.</p>
</Intro>

    <FileHeader filename="service.yaml" />
    <Row last>
      <p slot="docs">Services automaticamente ganham registros DNS. Este Service recebe DNS: <code>my-app.production.svc.cluster.local</code> com um registro A apontando para o ClusterIP.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app
  namespace: production
spec:
  ports:
    - port: 80
  selector:
    app: my-app
```
      </Fragment>

  </tbody>

<table class="example-table">

    <TerminalHeader cmd="curl http://my-app" />
    <Row last terminal>
      <p slot="docs">Resolução DNS do mais curto ao FQDN. Mesmo namespace: apenas nome do service. Cross-namespace: <code>service.namespace</code>. Com sufixo svc: <code>service.namespace.svc</code>. FQDN completo (raramente necessário): <code>service.namespace.svc.cluster.local</code>.</p>
      <Fragment slot="code">
```bash
$ curl http://my-app
Hello from my-app!

$ curl http://my-app.other-namespace
Hello from my-app!

$ curl http://my-app.other-namespace.svc

$ curl http://my-app.other-namespace.svc.cluster.local
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="headless-service.yaml" />
    <Row last>
      <p slot="docs">Headless Services (<code>clusterIP: None</code>) retornam IPs de Pods diretamente ao invés de um ClusterIP. DNS retorna todos os IPs de Pods correspondentes. Essencial para StatefulSets e load balancing do lado cliente.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-db
spec:
  clusterIP: None
  ports:
    - port: 5432
  selector:
    app: postgres
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-dns-config.yaml" />
    <Row last>
      <p slot="docs">DNS policy do Pod controla como Pods resolvem nomes. <code>ClusterFirst</code> é o padrão. Use <code>None</code> com <code>dnsConfig</code> customizado para casos especiais. Opções: Default, ClusterFirst, ClusterFirstWithHostNet, None.</p>
      <Fragment slot="code">
```yaml
spec:
  dnsPolicy: ClusterFirst
  dnsConfig:
    nameservers:
      - 8.8.8.8
    searches:
      - my-namespace.svc.cluster.local
    options:
      - name: ndots
        value: "5"
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <TerminalHeader cmd="kubectl get configmap coredns -n kube-system" />
    <Row last terminal>
      <p slot="docs">Configuração do CoreDNS está em um ConfigMap no kube-system. Customize para forwarding de DNS externo, domínios customizados ou caching. Pods recebem <code>/etc/resolv.conf</code> configurado pelo kubelet.</p>
      <Fragment slot="code">
```bash
$ kubectl get configmap coredns -n kube-system -o yaml
apiVersion: v1
kind: ConfigMap
data:
  Corefile: |
    .:53 {
        kubernetes cluster.local in-addr.arpa ip6.arpa {
           pods insecure
           fallthrough in-addr.arpa ip6.arpa
        }
        forward . /etc/resolv.conf
        cache 30
    }

$ kubectl exec my-pod -- cat /etc/resolv.conf
nameserver 10.96.0.10
search default.svc.cluster.local svc.cluster.local cluster.local
```
      </Fragment>
    </Row>
