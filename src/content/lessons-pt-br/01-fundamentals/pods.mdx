<Intro>
  <p>Um Pod é a unidade atômica de agendamento no Kubernetes. Ele envolve um ou mais containers que compartilham rede e armazenamento. Containers em um Pod se comunicam via <code>localhost</code> e compartilham o mesmo endereço IP, faixa de portas e volumes.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod.yaml" />
    <Row>
      <p slot="docs">Pods usam a API core <code>v1</code>. O <code>kind</code> informa ao Kubernetes qual recurso criar.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs">O <code>name</code> identifica unicamente o Pod dentro de seu namespace. Labels permitem seleção e agrupamento.</p>
      <Fragment slot="code">
```yaml
metadata:
  name: my-app
  labels:
    app: my-app
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs">O array <code>spec.containers</code> define os containers. Cada um precisa de um nome e imagem.</p>
      <Fragment slot="code">
```yaml
spec:
  containers:
    - name: app
      image: nginx:alpine
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Exponha portas para tornar o container acessível. <code>containerPort</code> é informativo, mas útil para documentação.</p>
      <Fragment slot="code">
```yaml
      ports:
        - containerPort: 80
```
      </Fragment>
    </Row>
  </tbody>
</table>

      <p slot="docs">Estados do ciclo de vida do Pod: <code>Pending</code> (aguardando agendamento ou pull de imagem), <code>Running</code> (pelo menos um container rodando), <code>Succeeded</code> (todos containers terminaram com sucesso), <code>Failed</code> (container terminou com erro).</p>
      <Fragment slot="code">
```bash
$ kubectl get pods -w
NAME     READY   STATUS    RESTARTS   AGE
my-app   0/1     Pending   0          0s
my-app   0/1     Pending   0          1s
my-app   0/1     ContainerCreating   0   2s
my-app   1/1     Running   0          5s
```
      </Fragment>
    </Row>

```bash
  Type    Reason     Age   From               Message

  Normal  Scheduled  10s   default-scheduler  Successfully assigned
  Normal  Pulled     8s    kubelet            Container image pulled
  Normal  Started    7s    kubelet            Started container app
```

    <FileHeader filename="multi-container-pod.yaml" />
    <Row>
      <p slot="docs">O Kubernetes cria um container "pause" que mantém o namespace de rede. Containers de app se juntam a este namespace, compartilhando o mesmo IP e usando <code>localhost</code>.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-metrics
spec:
  containers:
    - name: web
      image: nginx
      ports:
        - containerPort: 80
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs">Pods multi-container são para workloads fortemente acoplados. Padrões comuns: sidecar (logging, proxies), ambassador (proxy para serviços externos), adapter (transforma saída).</p>
      <Fragment slot="code">
```yaml
    - name: metrics
      image: prom/node-exporter
      ports:
        - containerPort: 9100
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="sidecar-pod.yaml" />
    <Row>
      <p slot="docs">O padrão sidecar usa um volume compartilhado. A aplicação principal escreve logs, e o container sidecar os envia.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-with-sidecar
spec:
  containers:
    - name: app
      image: my-app:v1
      ports:
        - containerPort: 8080
      volumeMounts:
        - name: logs
          mountPath: /var/log/app
```
      </Fragment>
    </Row>
    <Row>
      <p slot="docs">O sidecar lê do mesmo volume e encaminha logs para sua infraestrutura de logging.</p>
      <Fragment slot="code">
```yaml
    - name: log-shipper
      image: fluent-bit:latest
      volumeMounts:
        - name: logs
          mountPath: /var/log/app
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><code>emptyDir</code> cria um diretório temporário que é compartilhado entre containers e deletado quando o Pod termina.</p>
      <Fragment slot="code">
```yaml
  volumes:
    - name: logs
      emptyDir: {}
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod-resources.yaml" />
    <Row>
      <p slot="docs">Requests e limits de recursos controlam alocação de CPU/memória. Sem limits, um Pod pode consumir todos os recursos do node.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-with-resources
spec:
  containers:
    - name: app
      image: my-app:v1
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><code>requests</code> são recursos garantidos usados para agendamento. <code>limits</code> são o máximo permitido. CPU é em millicores (100m = 0.1 cores).</p>
      <Fragment slot="code">
```yaml
      resources:
        requests:
          memory: "128Mi"
          cpu: "100m"
        limits:
          memory: "256Mi"
          cpu: "500m"
```
      </Fragment>
    </Row>
  </tbody>
</table>
