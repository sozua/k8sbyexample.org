<Intro>
  <p>LoadBalancer provisiona um load balancer externo do seu provedor cloud (AWS ELB, GCP LB, Azure LB). O tráfego é roteado para seus Pods. Funciona apenas em ambientes suportados.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="service-loadbalancer.yaml" />
    <Row last>
      <p slot="docs">Defina <code>type: LoadBalancer</code> para provisionar um load balancer cloud. O cloud controller cria e configura o LB automaticamente.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  type: LoadBalancer
  ports:
    - port: 80
      targetPort: 8080
  selector:
    app: my-app
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <TerminalHeader cmd="kubectl get svc my-app -w" />
    <Row last terminal>
      <p slot="docs">O IP externo aparece no status do Service uma vez provisionado. Isso pode levar alguns minutos dependendo do provedor cloud.</p>
      <Fragment slot="code">
```bash
$ kubectl get svc my-app -w
NAME     TYPE           CLUSTER-IP    EXTERNAL-IP   PORT(S)        AGE
my-app   LoadBalancer   10.96.0.100   <pending>     80:31234/TCP   10s
my-app   LoadBalancer   10.96.0.100   34.123.45.67  80:31234/TCP   45s

$ curl http://34.123.45.67
Hello from my-app!
```

    <FileHeader filename="service-lb-aws.yaml" />
    <Row last>
      <p slot="docs">Annotations específicas de cloud configuram o load balancer. Cada provedor tem opções diferentes para LBs internos, NLB vs ALB, etc.</p>
      <Fragment slot="code">
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: nlb
    service.beta.kubernetes.io/aws-load-balancer-internal: "true"
spec:
  type: LoadBalancer
  ports:
    - port: 80
      targetPort: 8080
  selector:
    app: my-app
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">

    <FileHeader filename="service-external-traffic.yaml" />
    <Row>
      <p slot="docs"><code>externalTrafficPolicy: Cluster</code> (padrão) faz balanceamento entre todos os nodes. Tráfego pode saltar entre nodes, causando latência extra e perdendo IP de origem.</p>
      <Fragment slot="code">
```yaml
spec:
  type: LoadBalancer
  externalTrafficPolicy: Cluster
```
      </Fragment>
    </Row>
    <Row last>
      <p slot="docs"><code>externalTrafficPolicy: Local</code> roteia tráfego apenas para nodes com pods. Preserva IP de origem e reduz latência, mas requer pods em todos os nodes recebendo tráfego.</p>
      <Fragment slot="code">
```yaml
spec:
  type: LoadBalancer
  externalTrafficPolicy: Local
  ports:
    - port: 80
      targetPort: 8080
  selector:
    app: my-app
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <TerminalHeader cmd="kubectl get svc my-app -o wide" />
    <Row last terminal>
      <p slot="docs">Com política <code>Local</code>, verifique se pods rodam em nodes recebendo tráfego. Use DaemonSet ou pod anti-affinity para garantir cobertura. Nodes sem pods retornam connection refused.</p>
      <Fragment slot="code">
```bash
$ kubectl get svc my-app -o yaml | grep externalTrafficPolicy
  externalTrafficPolicy: Local

$ kubectl get pods -o wide -l app=my-app
NAME       NODE      IP
my-app-1   node-1    10.244.1.5
my-app-2   node-2    10.244.2.8

$ kubectl logs my-app-1
Received request from 203.0.113.50
```

    </Row>
