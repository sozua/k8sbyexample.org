<Intro>
  <p>Pod affinity agenda Pods em nodes onde Pods específicos já estão rodando. Use para: co-localizar serviços relacionados, reduzir latência de rede, localidade de dados.</p>
</Intro>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod-affinity.yaml" />
    <Row last>
      <p slot="docs">Pod affinity é definida em <code>spec.affinity.podAffinity</code>. <code>labelSelector</code> corresponde Pods alvo. <code>topologyKey</code> define o escopo (mesmo node, zone, etc.).</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: cache
          topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

<table class="example-table">
  <tbody>
    <FileHeader filename="pod-affinity-types.yaml" />
    <Row last>
      <p slot="docs">Primeiro exemplo: <code>required</code> é uma restrição rígida - Pod não agenda se não satisfeita. Segundo exemplo: <code>preferred</code> é flexível - scheduler tenta mas não garante. Weight determina força da preferência (maior = mais forte).</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        - labelSelector:
            matchLabels:
              app: cache
          topologyKey: kubernetes.io/hostname
---
spec:
  affinity:
    podAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: cache
            topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="topology-keys.yaml" />
    <Row last>
      <p slot="docs"><code>topologyKey</code> define o escopo. <code>kubernetes.io/hostname</code> = mesmo node, <code>topology.kubernetes.io/zone</code> = mesma AZ, <code>topology.kubernetes.io/region</code> = mesma região. Keys customizadas para agendamento rack-aware.</p>
      <Fragment slot="code">
```yaml
topologyKey: kubernetes.io/hostname

topologyKey: topology.kubernetes.io/zone

topologyKey: topology.kubernetes.io/region

topologyKey: rack.example.com/rack-id
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-affinity-expressions.yaml" />
    <Row last>
      <p slot="docs">Use <code>matchExpressions</code> para correspondência complexa de labels. Suporta operadores: <code>In</code>, <code>NotIn</code>, <code>Exists</code>, <code>DoesNotExist</code>. Múltiplas expressions usam lógica AND.</p>
      <Fragment slot="code">
```yaml
podAffinity:
  requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchExpressions:
          - key: app
            operator: In
            values:
              - cache
              - queue
          - key: environment
            operator: In
            values:
              - production
      topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>
</table>

    <FileHeader filename="pod-affinity-namespace.yaml" />
    <Row last>
      <p slot="docs"><code>namespaceSelector</code> corresponde Pods entre namespaces. Por padrão, affinity só considera Pods no mesmo namespace. Use para dependências cross-namespace.</p>
      <Fragment slot="code">
```yaml
podAffinity:
  requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchLabels:
          app: cache
      namespaceSelector:
        matchLabels:
          team: platform
      topologyKey: kubernetes.io/hostname
---
    - labelSelector:
        matchLabels:
          app: cache
      namespaces:
        - shared-services
      topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>
  </tbody>

    <FileHeader filename="pod-combined-affinity.yaml" />
    <Row last>
      <p slot="docs">Combine affinity com anti-affinity para posicionamento complexo. Co-localize com dependências mas espalhe entre nodes. Padrão comum para aplicações stateful com seus caches.</p>
      <Fragment slot="code">
```yaml
spec:
  affinity:
    podAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: redis
            topologyKey: kubernetes.io/hostname
    podAntiAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
        - weight: 100
          podAffinityTerm:
            labelSelector:
              matchLabels:
                app: my-app
            topologyKey: kubernetes.io/hostname
```
      </Fragment>
    </Row>

    <Row last terminal>
      <p slot="docs">Debug problemas de pod affinity verificando eventos do scheduler. Pods Pending mostram por que nenhum node foi selecionado. Verifique se Pods alvo existem e têm labels correspondentes.</p>
      <Fragment slot="code">
```bash
$ kubectl describe pod my-app
Events:
  Type     Reason            Age   Message
  Warning  FailedScheduling  10s   0/3 nodes available:
    3 node(s) didn't match pod affinity rules

$ kubectl get pods -l app=cache --show-labels
NAME      READY   STATUS    LABELS
cache-1   1/1     Running   app=cache,env=prod

$ kubectl get pods -l app=cache -o wide
NAME      READY   NODE
cache-1   1/1     node-1

$ kubectl get pod my-app -o jsonpath='{.spec.affinity}' | jq
```
